## What this model is

A **character-level decoder-only language model**, trained from random initialisation
on this repository's own text. It predicts the next character given up to 128
characters of context.

It is the first language model in this project that actually exists. Every previous
route to one was blocked: `huggingface.co` and `download.pytorch.org` are unreachable,
`llama-cpp-python` publishes no manylinux x86_64 wheel for any version, and there is
no `.gguf` or `.safetensors` anywhere on the host. Those obstacles apply to *adapting
someone else's* checkpoint. Training from nothing needs a corpus and compute, and
both were already here.

Implementation: `services/fabric/fabric/lm/` — **pure NumPy**, no PyTorch, no GPU, no
network. Every gradient is derived by hand and checked against a central finite
difference.

## Intended use

**Demonstrating that the training pipeline works end to end on conventional
hardware.** Data validation, a leak-proof corpus split, a hand-derived backward pass,
an optimiser, held-out evaluation against computed baselines, a versioned card and a
release gate that can refuse — all of it runs, reproducibly, with no external
dependency.

## Out of scope

- **Not a chat assistant.** It does not follow instructions and has no safety
  behaviour. It is reachable from `/api/chat`, where an unpinned request is refused with
  `model_not_instruction_tuned` (501) and a pinned request returns a continuation
  labelled as one; serving it as an assistant would misrepresent it. (This sentence was
  corrected — see [Corrections](#corrections).)
- **Not a general-purpose model.** It has no world knowledge beyond 1.38 MB of
  repository text.
- **Not compared to any pretrained model.** No such comparison was possible, and none
  is claimed anywhere.

## Evaluation

Held-out perplexity on a **file-disjoint** validation split — no document contributes
to both sides — against three baselines computed from the **same training statistics**
and scored on the **same 165,120 held-out tokens**.

| | Perplexity | Bits/char |
|---|---|---|
| `uniform` (`ln 143`) | 143.0000 | 7.1599 |
| `unigram` (training frequencies) | 35.2895 | 5.1414 |
| `bigram` (`P(next\|prev)`, training adjacencies) | 15.9109 | 3.9917 |
| **Aetheris Lite LM** | **4.4033** | **2.1386** |

**Verdict: beats the strongest baseline.** `perplexityVsBigram` = **0.276748**, i.e.
the model's perplexity is 27.7% of the bigram's — **3.61× better** than the best
non-neural baseline. That ratio, not the raw perplexity, is what the release gate
requires to be ≤ 1.0.

The baselines are why this number means anything. A perplexity on its own depends on
the vocabulary, the corpus and the tokenisation; `4.40` would be neither good nor bad
without the bigram's `15.91` next to it, measured identically.

## Limitations

Recorded on the card itself, generated by `model_limitations()` so they cannot be
forgotten when a card is produced:

- trained from random initialisation; not derived from any pretrained base model
- character-level base model: it predicts the next character of repository text and
  follows no instructions (359,136 parameters, vocabulary of 143)
- output quality is low: this demonstrates the pipeline, not a usable assistant
- reachable from `/api/chat`, where an unpinned request is refused with
  model_not_instruction_tuned (501): it continues text and does not answer questions, and
  presenting it as an assistant would misrepresent it
- no comparison against any pretrained model was performed, and none is claimed

## Reproducibility

```bash
npm run lm:train
# then
cd services/fabric
python scripts/lm_release.py --report artifacts/aetheris-lite-lm-82392ef89074.report.json --version 0.1.0
```

The same command produces a **bit-identical** artifact.
`tests/test_lm_train.py::test_the_same_run_twice_produces_the_same_artifact` asserts
that on the weight bytes rather than on the loss, and a companion test asserts a
different model seed produces *different* weights — because reproducibility would be
meaningless if the seed did nothing.

## A bug this model found before it was trained

The numeric gradient check failed on its first run, and reported exactly one line:

```
pos: exceeds tolerance by 1.611e-01 at index 37
     (numeric 1.69456020e-01, analytic 8.39019590e-03)
```

The positional-embedding gradient scattered using a `(T, B)` layout while the hidden
state is `(B, T)`, so every position received another position's gradient. No other
test in this repository would have caught it, and a training run would have looked
merely *worse than expected* rather than wrong. Both the fix and a negative control
(the bug reintroduced) are in `tests/test_lm_model.py`.
